# QSP PDF Guru — расширение 1С 0.3.2

## Исправление 0.3.2

- После чтения отсутствующей записи регистра повторно устанавливается ключ `Задание`. Это исправляет ошибку «Значение поля Задание не может быть пустым» при первом создании счёта для задания.
- Добавлена отдельная понятная проверка пустого идентификатора задания до обращения к сервису и регистру.

## Изменения 0.3.1

- Несоответствие выбранного договора поставщику, организации или валюте теперь показывается в окне подтверждения как предупреждение.
- После ответа «Да» расширение продолжает создавать непроведённый счёт с выбранным договором.
- Пустой договор больше не блокируется расширением заранее. Если он обязателен в основной конфигурации, штатная проверка 1С сообщит об этом при записи.
- Валюта документа по-прежнему должна совпадать с распознанной валютой счёта; это отдельная проверка бухгалтерских данных.

## Изменения 0.3.0

- Добавлена команда «Создать номенклатуру из выбранной строки» рядом с таблицей товаров.
- Перед созданием повторяется точный поиск по артикулу, затем по наименованию. Найденный элемент выбирается без создания дубля.
- Новая товарная позиция получает наименование, полное наименование, артикул, базовую единицу и ставку НДС; штатные значения группы и учётных настроек заполняет конфигурация 1С.
- Если единица скана не найдена однозначно, создание блокируется до ручного выбора единицы в строке.
- После создания справочники сразу повторно выгружаются на сервер, поэтому позицию можно подтвердить в текущем задании.
- В статусе показывается версия сервера и отдельная диагностика отсутствующих банковских реквизитов.

## Изменения 0.2.1

- Команда «Создать контрагента по счёту» перенесена из переполняемой верхней панели прямо под распознанные реквизиты поставщика.
- Кнопка видна там только при отсутствии контрагента с распознанным 12-значным БИН/ИИН.

## Изменения 0.2.0

- В форме видны распознанные наименование, БИН, адрес, КБЕ, ИИК, банк и БИК поставщика.
- При отсутствии точного совпадения по БИН появляется команда создания контрагента после подтверждения пользователя.
- При наличии контрагента команда создания скрыта; дубли по БИН блокируются повторной серверной проверкой.
- Адрес, КБЕ, банк и банковский счёт переносятся только из явно распознанных значений; основной счёт создаётся при корректных ИИК, БИК и валюте.
- Если банк уже есть, достаточно совпадения по БИК. Новый банк создаётся только при наличии его наименования.
- При единственном действующем договоре найденного контрагента и организации он выбирается автоматически; при нескольких вариантах выбор остаётся бухгалтеру.
- Созданная карточка сразу открывается для проверки. Контрагент и счёт не создаются без подтверждения пользователя.

## Изменения 0.1.8

- Контрагент и организация дополнительно ищутся непосредственно в справочниках 1С по распознанному БИН.
- Валюта подставляется по буквенному коду.
- Флаг «НДС включён в сумму» определяется по согласованию суммы строк с итогом.
- Ставка НДС строки подставляется из проверенного результата сервиса.

Этот архив содержит исходники нового расширения 1С. Сервер очереди и обновлённый промпт поставлены в QSP_PDFGuru_Bridge_v0.2.0_SOURCE.zip. Расширение подготовлено для «Бухгалтерии для Казахстана» 3.0.72.1 по предоставленной выгрузке метаданных. Существующий Invoice Vision и его БД не изменяются.

Для создания контрагента у пользователя должны быть штатные права 1С на запись контрагентов, банков и банковских счетов. Расширение не включает привилегированный обход прав.

После обновления сервера старые уже распознанные задания не получат новые банковские поля автоматически. Нажмите «Повторить», дождитесь обработки и затем «Получить результат».


## Диагностика 0.1.8

Форма показывает реальное описание ошибки соединения. Чтение единственной записи настроек не использует метод Выбран менеджера регистра и совместимо со старым режимом платформы.

## Совместимость 0.1.6

Получение имени загружаемого файла выполняется собственной клиентской функцией на базовых строковых операциях и не зависит от отсутствующей глобальной функции ИмяФайлаБезПути.

## Совместимость 0.1.5

Проверка расхождения итоговой суммы не использует недоступную глобальную функцию Абс и совместима с текущим языковым контекстом конфигурации.

## Совместимость 0.1.4

Основная конфигурация и расширение работают в режиме совместимости 8.3.14. Константы расширения, запрещенные платформой в режиме 8.3.15 и ниже, заменены независимым регистром сведений QSPPDF_Настройки.

## Исправление загрузки XML в 0.1.2

В 0.1.1 платформа сообщила «Отсутствует внутренняя информация (узел InternalInfo)» для 13 объектов. Добавлены полноценные GeneratedType с TypeId/ValueId в документ, восемь справочников, три константы и регистр сведений. Наборы типов взяты из предоставленной выгрузки конфигурации. Новые идентификаторы типов принадлежат расширению; UUID метаданных объектов и привязки ExtendedConfigurationObject сохранены. Пустые InternalInfo не используются.

Распакуйте 0.1.2 в новую папку и повторите загрузку расширения из XML на той же тестовой копии. Выбирайте корень, содержащий Configuration.xml. Если загружаете поверх частично загруженного QSPPDF_РаспознаваниеСчетов, загружайте в это же расширение: имена и UUID его объектов сохранены. Не загружайте в коммерческое или складское расширение и не заменяйте основную конфигурацию.

Локальная проверка теперь отклоняет исходники 0.1.1 и проверяет наличие, порядок, состав GeneratedType, имена и уникальность UUID в 0.1.2. Это проверка исходников, не подтверждение успешной загрузки платформой 1С. После загрузки ещё требуются проверка модулей, применимости и работа формы на копии.

## Формат поставки 0.1.2

Архив расширения имеет тот же формат исходников, что QazSher_Commercial_1C_v1.2.7: Configuration.xml, CommonModules, DataProcessors и другие объекты непосредственно в корне. Python-сервис остаётся отдельным компонентом. Этот архив не устанавливает и не заменяет расширения коммерческого отдела и склада.

В форме выделены четыре группы: очередь и статус, реквизиты и сопоставление, результат распознавания, настройки сервиса. Исправлены основной реквизит обработки, порядок секций формы, объявления пространств имён для типов и идентификаторы внутренних объектов, ранее скопированные из шаблона.

Добавлен BUILD_EXTENSION.ps1 по образцу коммерческого отдела. Для запуска распакуйте архив и из PowerShell вызовите:

```powershell
.\BUILD_EXTENSION.ps1 -OneCExe 'C:\Program Files\1cv8\ВАША_ВЕРСИЯ\bin\1cv8.exe' -TestBaseDirectory 'D:\1C_TEST_COPY' -UserName 'Администратор'
```

Укажите фактический путь к платформе и отдельную файловую копию вашей базы. Скрипт загружает расширение в конфигуратор этой копии, проверяет его и выгружает CFE в отдельный каталог build_logs. Основную конфигурацию он не заменяет, обновление конфигурации БД не выполняет. Просмотрите все журналы; создание CFE само по себе не подтверждает работоспособность формы.

Это исправленная поставка исходников. Компиляция, применимость заимствованных объектов, запуск формы и создание документов в вашей 1С остаются непроверенными. Для перехода с установленной 0.1.0 сначала требуется испытание на копии; схема регистра не изменена, но это не проверенная миграция рабочей базы.

Для сервиса используйте серверную часть прежнего QSP_PDFGuru_Bridge_v0.1.0_SOURCE.zip. Его старые исходники onec/extension заменены настоящим отдельным архивом 0.1.2. Email и пароль PDFGuru задаются в серверном .env; в 1С задаётся ключ сервиса.

## Готовность

- Сервер: реализованы общая FIFO-очередь, статусы, один браузерный обработчик, загрузка PDF/изображений, сопоставление, память подтверждённых соответствий и настройки входа через `.env`.
- Браузер: путь загрузки и получения JSON ранее проверен в авторизованном встроенном браузере PDF Guru на JPEG. Новый самостоятельный Playwright-обработчик и вход по email/паролю на сервере ещё не испытаны.
- 1С: подготовлены независимые XML/BSL-исходники расширения. **Готового проверенного `.cfe` в пакете нет.** На машине разработки платформа 1С не обнаружена, поэтому компиляция и пользовательская форма в 1С не проверены. Следующий обязательный этап — загрузить исходники и скомпилировать на копии вашей базы.
- Ничего не установлено на рабочие серверы; документы рабочей базы не создавались.

## Установка сервера приложений

1. Распакуйте пакет в отдельную папку на сервере приложений; не поверх старого Invoice Vision.
2. Требуется Python 3.11 x64. Выполните `install_windows.cmd`: устанавливается отдельное окружение и Chromium Playwright.
3. Откройте созданный `.env` на сервере. Установщик генерирует случайный `QSP_API_TOKEN`; перенесите его в настройку расширения «Ключ сервиса». Не публикуйте `.env` и `data/browser-profile`.
4. Заполните `QSP_PDFGURU_EMAIL` и `QSP_PDFGURU_PASSWORD`. Значения с пробелами или `#` заключайте в двойные кавычки. Пароль не передаётся в 1С, не включён в API-ответы, журнал или архив.
5. `QSP_HOST` по умолчанию 127.0.0.1. Для доступа с другого сервера задайте частный LAN-IP сервера приложений. В брандмауэре разрешите порт 8020 только серверу 1С. Вне доверенной локальной сети требуется HTTPS через обратный прокси; сервис не предназначен для прямой публикации в Интернет.
6. Запустите `run_windows.cmd`. Ключ и параметры перечитываются при перезапуске сервиса.
7. При необходимости ручного входа остановите обработчик, запустите `login_windows.cmd` через RDP, авторизуйтесь в появившемся браузере, затем снова запустите сервис. Профиль хранится на сервере. CAPTCHA/2FA автоматически не обходятся.

Не копируйте профиль Chrome из личного компьютера и не пытайтесь одновременно использовать профиль обработчика из двух процессов. На сервере должен быть один экземпляр сервиса. После закрытия RDP сеанса запущенный вручную процесс может завершиться при выходе пользователя: для постоянной эксплуатации настройте запуск `server.serve` в планировщике Windows под отдельной учётной записью с доступом к папке пакета; режим браузера по умолчанию headless.

## Установка исходников расширения 1С

1. Создайте резервную копию и отдельную тестовую базу. Не загружайте непроверенное расширение сразу в рабочую базу.
2. В конфигураторе копии откройте «Конфигурация → Расширения конфигурации», создайте отдельное расширение и загрузите конфигурацию расширения из XML-файлов корня распакованного архива, где находится `Configuration.xml`. Это загрузка **расширения**, не замена основной конфигурации.
3. Проверьте соответствие заимствованных объектов вашей базе, выполните проверку модулей, сохраните расширение и обновите конфигурацию БД копии. После исправления найденных платформой ошибок выгрузите `.cfe`. Эти действия на машине разработки не выполнялись.
4. Пользователям назначается дополнительная роль `QSPPDF_Пользователь`; существующие бухгалтерские права сохраняются. Расширение не выдаёт полные права. Сохранение общих настроек доступно пользователю с ролью `ПолныеПрава`.
5. Откройте новый раздел «Счета PDF Guru». Также обработка `QSPPDF_Счета` доступна через «Все функции / Функции для технического специалиста → Обработки». Пароль PDF Guru в форму не вводится.
6. Администратор задаёт адрес сервиса, ключ и единый идентификатор этой базы. Все пользователи одной базы должны использовать один идентификатор. Разные базы — разные идентификаторы.
7. Нажмите «Выгрузить справочники». Повторяйте выгрузку после изменения контрагентов, организаций или номенклатуры.

## Работа бухгалтера

- «Загрузить счёт»: PDF/изображение отправляется в очередь. В таблице видны файл, пользователь, этап и позиция. Обновление каждые 5 секунд. Распознавание выполняется на сервере приложений, 1С не ожидает ответ ИИ в длительном серверном вызове.
- Текущее задание указано отдельным полем; можно выбрать строку очереди или недавнего задания. Виден текущий документ другого пользователя этой же базы.
- После завершения — «Получить результат». Выводятся исходный JSON, ошибки, сомнения и JSON вариантов сопоставления. Заполните поставщика, организацию, договор, валюту и строки справочника.
- Выбор номенклатуры подставляет базовую единицу. Проверьте её совпадение с единицей скана; автоматического пересчёта упаковок нет.
- «Подтвердить сопоставление» запоминает соответствие имени/артикула/единицы товара конкретному поставщику. Дубликаты БИН/артикулов не выбираются автоматически. Нечёткое имя — только предложение, не готовое решение.
- «Создать счёт» спрашивает подтверждение и создаёт **непроведённый** документ с оригиналом через имеющийся в конфигурации модуль `РаботаСФайлами`. На копии необходимо проверить именно этот вызов BSP и права прикрепления файлов.
- Для НДС пользователь выбирает ставки строк и флаг «НДС включён в сумму»; режим «Без НДС» отдельно от 0%. Итог сверяется с выбранным режимом. Поддерживаемая валюта автоматического импорта в этой версии — KZT; курс иностранной валюты не выдумывается.
- Ошибки распознавания блокируют создание: такой документ следует исправлять вручную в 1С по скану; редактор исправления JSON в этой версии не добавлен.
- Повтор создания того же задания возвращает ранее созданный документ через регистр `QSPPDF_ИмпортированныеЗадания`. Другой файл с тем же поставщиком, организацией, входящим номером и датой блокируется как возможный дубликат. Документ с прежним заданием, помеченный на удаление, автоматически не пересоздаётся.

## Очередь и восстановление

Задания и соответствия сохраняются в `data/bridge.sqlite3`, оригиналы — в `data/uploads`. При аварийном перезапуске незавершённое задание получает ошибку «Обработка прервана». Автоматический повтор после неопределённого исхода не выполняется. После восстановления входа выберите такое задание и нажмите «Повторить». При необходимости для старых заданий обновите справочники и повторно подтвердите сопоставление.

Не удаляйте `data` для исправления ошибки. Резервное копирование делайте при остановленном сервисе, включая БД и оригиналы; профиль браузера и `.env` содержат доступ к аккаунту и должны храниться отдельно с ограниченным доступом. Архив поставки не содержит этих данных.

## Авторизация и ограничения

Вход по email/паролю реализован для стандартной формы сайта с email/password и кнопкой Log in/Sign in/Войти. Реальная форма входа в текущем аккаунте не была проверена: тест проводился в уже авторизованной сессии. Если сайт меняет форму, вводит CAPTCHA, OTP или другой способ входа, очередь останавливается и потребуется ручная авторизация.

Текущие селекторы обработки основаны на проверенном интерфейсе: Add file → From my device → Upload complete → textbox → Send → code. При изменении сайта возможна остановка. Новый диалог открывается для каждого задания; наличие старого блока ответа блокирует отправку. Подписка и лимиты PDF Guru не изменяются.

Начальные лимиты программы: 20 МБ, 15 страниц PDF, 240 секунд ожидания ответа. Они настраиваются в `.env` и не являются лимитами PDF Guru. Число страниц известно локально; подтверждение полноты распознавания всех страниц на стороне PDF Guru ещё требует проверки на многостраничном образце.

Ключ сервиса даёт доступ к данным компании и предназначен для доверенного сервера 1С. API не является системой индивидуальной авторизации бухгалтеров; имена пользователей передаются серверным кодом 1С. Прямой доступ к API не предоставляется внешним пользователям.

## Проверки

Локально проверены API и серверная логика с имитацией браузера: FIFO для двух пользователей, атомарное получение задания при конкуренции, восстановление, идемпотентная загрузка, разделение баз, неоднозначный БИН, подтверждённые соответствия, удалённая номенклатура, арифметика/НДС, валидность JSON, приостановка при необходимости входа, авторизация API и подтверждение импорта.

Исходники XML проверены на синтаксис и связность имён формы/модулей. Это **не компиляция 1С** и не проверка на рабочем сервере. На копии ещё нужны проверка расширения, создание непроведённого счёта, прикрепление файла, выбор справочников и работа двух сеансов.
